Why it matters

When a value from outside is concatenated straight into a SQL statement, an attacker can put SQL syntax in that value to read other customers' orders or change data.

How to fix it

  1. Pass the value as a bind parameter (?) instead of concatenating it.
  2. Look for other queries built the same way and fix them together.

Code

46public List<Order> findByCustomer(String customerId) {
47    // Orders by customer
48    String sql = "SELECT * FROM orders WHERE customer_id = '" + customerId + "'";49    return jdbcTemplate.query(sql, orderMapper);
50}
AI judgmentAI: likely true positiveConfidence 0.95

customerId flows from the request into the SQL statement without validation. This location can actually be exploited.

Suggested patch

- String sql = "SELECT * FROM orders WHERE customer_id = '" + customerId + "'";- return jdbcTemplate.query(sql, orderMapper);+ String sql = "SELECT * FROM orders WHERE customer_id = ?";+ return jdbcTemplate.query(sql, orderMapper, customerId);
